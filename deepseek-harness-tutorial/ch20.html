一句话总结

💡 如果只记一句话

DeepSeek Harness 是一台「把模型包成能干活智能体」的机器：它把一切做成可替换的 Cordis 插件，把每一步事实写成可回放的会话日志，用一次「组装上下文 → 调模型 → 执行工具 → 记录结果」的循环驱动，再靠能力 seam 让文件、shell、模型、子代理都能整体替换。

术语速查

术语一句话
Harness把模型包成能干活的智能体的软件层（上下文+调用+工具+记录+循环+护栏）
Cordis / 插件底层插件框架；一切能力都是插件，注册是可逆副作用
ctx / Service服务容器；ctx.tools / ctx.llm / ctx.sessions 等
seam（能力接缝）可替换能力 = Service Definition + Provider + Consumer 三件套
Turn（轮次）一次「把用户输入干完」的全过程，含零到多个 Step
Step（步骤）一次模型请求 + 它引发的工具执行
Session / 日志仅追加的 SessionEvent 日志，唯一真源
surface产生模型消息的事件子集；历史由它投影而来
derived historyderiveMessages() 从日志算出的 Message[]
waterfall环绕中间件式事件，必须 next() 才委托下游
compaction上下文压缩；追加带 surfaceOp:replace 的摘要消息遮蔽旧区间
subagent被委派的子 agent（spawn/fork/外部后端）
workflow模型写的 JS 编排脚本，扇出到多个子 agent
goal附着在会话上的持久目标，按修订号演进阶段
profile / bundle / patch配置档 / 组合包 / 按 id 替换整段 config 的补丁
fail-closed拿不准就拒绝（审批、沙箱）
模型可见 ⟺ 已记录能进模型的东西必须能从日志重建

🧸 最后送你三句话
  1. 先找「它是什么」：任何一个新概念，先在术语表或 docs/subsystems 里定位它是 Service、事件、还是数据结构。
  2. 再问「它挂在哪」：用第 4 章的「归属表」，看它属于哪个 seam / 哪个事件域。
  3. 最后看「它怎么被记录」：凡是影响模型看到的，就去日志里找对应事件——这是 DSH 的万能钥匙。
