组装一台 DSH：Profile 与组合包

既然一切皆插件，那「启动 dsh web」到底发生了什么？答案是：它按顺序把好几层「插件清单」叠起来，拼出一棵完整的插件树。理解 Profile（配置档） 与 组合包（Bundle），你才知道 DSH 是怎么「组装」出来的。

🎯 学完这一章，你会明白
  • Profile 与 Bundle 分别是什么，各自在 package.json 里怎么声明；
  • 启动时那几层 patch 是按什么顺序叠加的；
  • dsh-base 提供了什么，web/headless/sdk/acp 各自加了什么；
  • 怎么用 --dump-config 看自己机器上真实的插件树。
🧸 小学生版：装修套餐 + 改造清单

装修公司给你三样东西：

  • Profile（配置档）＝你选的「整体套餐」，比如「拎包入住版 web」。它只写着「我要哪几个套餐包、我自己的改造清单在哪」。
  • Bundle（组合包）＝一个个「标准包」，比如「水电基础包（dsh-base）」「智能家居包（dsh-web-app）」。每个包本身是一张家具清单。
  • patch（补丁/改造清单）＝一张张「把 X 换成 Y、再加一个 Z」的指令。按顺序叠上去，后叠的覆盖先叠的。

最终你看到的房子（运行中的插件树），就是这些清单从空房子开始、一层层叠出来的结果。

三个关键词

Profile
存放在 Harness home 里的「具名组装」。列出自己叠放的组合包、树外插件，以及用户自己的 cordis.patch.yml。随发行版交付 web / headless / sdk / sdk-minimal / acp 五个模板。
Bundle
Cordis 配置项 + 挂载代码的分发格式。它插入的内容始终可以被上层 patch 覆盖。
patch
一条按 id 定位的指令：替换某个条目整个 config，或插入一个新条目。

它们在各自的 package.json 里用 dsh 字段声明自己：dsh.profile 列出一个 profile 的组合包，dsh.bundle 指向一个组合包的 patch 文件。

packages/bundle/base/package.json
{
  "name": "@deepseek-ai/dsh-base",
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" }
  }
}

启动时：五层叠加

运行时，这些层依次应用在一个空条目列表之上（后者覆盖前者）：

① Profile 中有序的组合包 dsh-base → dsh-web-appbundle
② 各组合包自己的 cordis.patch.yml 每个包自带的家具清单patch
③ Home patch 用户级 cordis.patch.ymlpatch
④ --patch overlay 命令行临时覆盖patch

从空列表开始，每叠一层，可用的插件就多一批；越靠上优先级越高。
💡 「替换整个 config」是关键细节

一条 patch 不是「合并进」目标的 config，而是替换它的整个 config。所以当你想改某个插件的一两个字段时，必须把想保留的其它字段也一起写出来。这也是为什么「不同模式专用的插件行」各自重述完整配置——保证任何一行最多只属于一个组合包层加用户层。

随发行版交付的组合包

组合包作用
dsh-base共享第一层：模型适配器、完整工具集、持久化、沙箱与审批策略、设置、凭据、遥测。web / headless / sdk / acp 都基于它。
dsh-web-app在 base 之上加浏览器应用：HTTP 服务器、Web 前端、客户端插件、RPC 网关。
dsh-headless加一个不带服务器的一次性运行器，跑完一个任务就退出（适合 CI、脚本）。
dsh-sdk-app加一个 SDK JSON-RPC 服务器，让外部程序通过 stdio 驱动 DSH。
dsh-acp-app加一个仅用于自动化的 ACP（Agent Client Protocol）服务器。
dsh-sdk-minimal刻意保留的例外：不应用 base，而是拥有一棵完整、显式的独立 SDK 配置树，用于最小化嵌入。

dsh-base 提供的「开箱即用」能力，包括：DeepSeek 模型连接、文件编辑 / shell / web 搜索 / HTTP 抓取 / 子代理 / 任务与目标跟踪等完整工具集、跨重启的持久会话，以及默认权限策略——把文件写入限制在工作区内，危险操作前征询许可。

看一眼真实的插件树

不用猜，你可以直接让 DSH 打印它启动时用的配置树：

dsh --profile web --dump-config

它打印出的任何条目，都可以被你自己写的 patch 替换。比如在 profile 的 cordis.patch.yml 里加一个条目，就能给所有 agent 多挂一个工具：

profile 的 cordis.patch.yml —— 插入一个新工具行（示意）
- insert:
    - id: tool-str-replace-editor
      name: '@deepseek-ai/dsh-tool-str-replace-editor'
      config:
        maxOutputChars: 16000
🧩 和「一切皆插件」的关系

现在你能把第 2、3 章连起来了：Cordis 提供了「插件 + 上下文 + 事件 + effect」这套机制；Profile / Bundle / patch 则是「如何把一堆插件按层次组合成产品」的配置语言。一个是发动机，一个是装配说明书。

🧪 小测验
关于 patch 的行为，下面哪句是对的？
答案：B。patch 按 id 定位条目并替换整个 config。想保留的字段必须重述，否则会丢失。
🧪 小测验
web、headless、sdk、acp 四个 profile 共享的第一层组合包是？
答案：B（dsh-base）。它提供模型访问、工具、持久化与安全默认值；sdk-minimal 是唯一刻意不基于 base 的例外。
