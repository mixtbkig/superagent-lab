全局架构：一次请求的完整旅程

前三章我们有了「harness 是身体」「循环是心跳」「一切皆插件」三个直觉。现在把它们合起来：从你在 Web 界面按下发送，到模型回复、工具执行、日志落盘、界面更新——中间到底经过了哪些包、哪些事件？这一章是整张地图。

🎯 学完这一章，你会明白
  • 仓库目录怎么分（apps / packages / native / docs / vendor / python）；
  • 「核心六包」各自负责什么、用什么 ctx 键；
  • 三类事件域：会话事件、Agent 事件、能力事件；
  • 一次轮次（turn）从头到尾的完整事件流；
  • 想加新功能时，应该挂到哪个扩展点。
🧸 小学生版：一家大公司怎么运转

把 DSH 想成一家公司：apps/ 是前台门店（Web、桌面、CLI）；packages/ 是各个部门（研发、财务、后勤……共 372 个）；native/ 是造工具的车间；docs/ 是公司手册；vendor/ 是外包来的通用制度（Cordis）。你发出的请求，就是一份工单，从门店前台一路流转到各部门，最后带着成果回到你手上。

核心六包：引擎的六个零件

包职责ctx 键
core/session仅追加的 SessionEvent 日志与内存存储——唯一真源ctx.sessions
core/system-prompt提示词片段与工具 schema 的组装ctx.systemPrompt
core/tools作用域化工具注册表 + 受把关的执行流水线ctx.tools
core/agentAgent 接口、活跃注册表、发起者作用域、agent/* 事件ctx.agents
core/agent-loop实现该接口的默认循环驱动器ctx.agentLoop
llm/llm消息 / 流式词汇表与适配器 seamctx.llm

还有一个小而关键的 core/scope——它不是服务，而是一个零依赖库（createScope/scopeTarget），被 session 与 system-prompt 复用，用来实现「按 agent 作用域」的注册。

一次轮次，正好按固定路径流过这六个包：agent-loop 认领提示词 → session 开轮次 → system-prompt 组装前缀并派生历史 → llm 流式请求 → tools 分发工具 → 每个事实回写 session 供下一步派生。

三类事件：分清楚，才找得到扩展点

📒 会话事件 durable
turn/start、user/message、assistant/message、tool/call…… 追加到日志、经 session/event 广播。必须在重载后依然存在的事实用它。
⚡ Agent 事件 live
agent/*：inbox、步骤、状态、请求、验证、续跑。携带活跃 Agent。要观察或拦截进行中的工作用它。
🔌 能力事件 policy
fs/*、tools/*、telemetry/*…… 无需 import 循环就能给某个 seam 附加策略或适配器。

💡 记住三条主线，后面就不会迷路
  1. 日志是唯一真源：所有事实先写 session，模型历史由 deriveMessages() 从日志算出来。
  2. 事件分为可回放（session/*）与实时（agent/*）：SDK 要 transcript 就读 session/event；要队列与状态就读 agent/*。
  3. 能力都要能被替换：新增能力挂在 seam 上（在 ctx.<key> 注册），不要改循环。

想加新功能？先看这张归属表

你想…机制
加一个模型提供方在 ctx.llm 上注册其适配器
加一个面向模型的能力（工具）在 ctx.tools 上注册；schema 自动进提示词组装
加 shell 执行 / 持久终端注册 ctx.shell / ctx.terminals 后端
加一条人类命令（/xxx）在 ctx.commands 上注册，无需模型轮次即可分派
拦截请求 / 工具 / 轮次用对应的 agent/* 或 tools/* 事件；agent/turn-stopping 能终止轮次
给模型加可见上下文调用 agent.inject()，它落到下一次获准的请求里
加 UI 或编辑器集成驱动 ctx.agents，并从 session/event 渲染
新增持久会话状态扩展 SessionEventMap，从日志渲染与回放
换一种后端存会话实现 SessionPersistence（create/open/stat/list/export）

🧪 小测验
如果某个事实「必须在重新加载后依然存在」，它应该走哪类事件？
答案：B。会话事件是持久事实，会追加到日志并可回放；agent/* 是实时协调，进程重启就没了。
🧪 小测验
「一个轮次（turn）可以包含零个步骤（step）吗？」
答案：A。文档明确：reject、空输入或 pre-step 失败，可以关闭一个「没有 step」的轮次。
