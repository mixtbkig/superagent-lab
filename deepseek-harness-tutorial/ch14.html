技能、MCP 与运行时扩展

前三层「能力」来自 DSH 自己：工具、子代理、workflow。但真实世界的能力远不止这些——你有自己的操作手册（Skill）、外部工具服务器（MCP）、甚至想让模型在运行时自己「装一个新插件」（extensions）。这一章讲 DSH 如何把这些都接进来，而核心一行不改。

🎯 学完这一章，你会明白
  • Skill 是什么、发现优先级如何排、目录怎么注入、正文怎么按需加载；
  • MCP 如何把外部服务器的工具变成原生工具，资源与指令怎么处理；
  • extensions：模型在运行时挂载/卸载动态 Cordis 插件；
  • Claude Code 模组桥接与人类命令（slash command）的区别。
🧸 小学生版：兴趣班手册、外挂工具箱、现场改装
  • Skill＝一本本「兴趣班手册」（SKILL.md）。书架上有目录（只有标题+一句话简介），需要时才翻开某本细读。
  • MCP＝校外的「工具供应商」。你告诉他你要什么，他提供一整套工具，学校把它们当自己的工具用。
  • Extensions＝允许在课堂上现场改装机器人：模型自己写一个小插件，装上、用、再拆掉。
  • Commands＝写在黑板上的「快捷指令」，比如 /compact，人一喊就执行，不经过模型。

Skill：可复用的「操作手册」

Skill 是可选的指令，不是会话事件。它由三部分组成：Service Definition（ctx.skills）、本地提供方（dsh-skill-filesystem）、以及面向模型的消费者（dsh-tool-skill）。

发现优先级

Rank来源根目录
100project-dsh<projectRoot>/.dsh/skills
200project-agents<projectRoot>/.agents/skills
300customConfig.customSkillDirs
400user-dsh<dshHome>/skills
500user-agents<agentsHome>/skills
600bundled配置了 bundledSkillDir 时使用该目录

skill 名必须是 kebab-case。本地提供方接受两种布局：目录包 <name>/SKILL.md，或扁平文件 <name>.md。重名时 rank 越小越优先；同一层内按提供方顺序、本地顺序裁决。

目录注入 ≠ 正文加载

发现 skills只拿 name + description
→
注入 <system-reminder>模型看到「有这些技能」
→
模型调用 skill({name})按需加载正文
→
返回 <skill_content>正文 + 资源引导
目录只有名字与描述（≤500 字），不含正文、路径、来源；正文只在模型真的调用时才读取。这样上下文不会被一堆手册撑爆。
  • 目录作为持久的 user/message（<system-reminder>）注入，随变化替换；压缩把它遮住后，下次观测会重建。
  • SkillInvocationPolicy 把调用控制拆成两个独立布尔：modelInvocable / userInvocable。仅用户可调用的 skill 不会出现在模型目录里。
  • skill({name}) 工具会再次检查 isModelInvocable，并按调用方 agent 的 cwd 重新读取正文。

MCP：把外部工具接成原生工具

模型上下文协议（Model Context Protocol，MCP）让模型使用外部服务器提供的工具。DSH 的做法很干净：每个已配置服务器提供普通 Harness 工具，因此它们自动继承取消、权限检查、结果记录、图像输出等一整套流水线能力。

🔌 连接
每服务器一个 @deepseek-ai/dsh-mcp-client 条目；支持 stdio 与 Streamable HTTP；官方 SDK 负责协商与取消。
🧰 工具适配
发现到的工具适配到 Harness 执行过程；公开工具名包含服务器名，避免不同服务器同名冲突。
📚 资源
共享 mcp-resources 服务提供资源列举/读取；需显式指定服务器名。
📝 指令
服务器的非空指令作为带归属的作用域章节，进入已记录的系统提示词。

注意：MCP 客户端不发布共享的 ctx.mcp 服务，它就是工具注册表的一个消费者；连接失败不会移除共享资源工具（只要可见的客户端条目还激活）。

Extensions：运行时自我改装

这是最「科幻」的一块：extensions 允许 agent 在运行时挂载/卸载动态 Cordis 插件。模型写一段插件定义（cordis_define），经审批后装进正在运行的 Host（必要时还有浏览器半侧）。

模型写插件定义
→
审批 / 版本检查
→
Host 挂载（cordis-host-runner）
→
（可选）Client 半侧挂载
⚠️ 能力越大，责任越大

动态插件拥有宿主权限。所以这块全是「显式启用 + 审批 + 版本保护 + 运行时检查 + 生命周期清理」。别把它当成随手可用的玩具——它是给高级自动化场景准备的。

Claude Code 模组 & 人类命令

🧩 Claude Code 模组桥接

实验性包 claude-code-mods 能加载为 Claude Code 写的 hook 模组（defineMod），把 session.start、tool.call、prompt.submit 等事件映射到 DSH 的 agent/*、tools/execute 上。文档里有一张逐条对比表，说明哪些行为一致、哪些不同（比如 next() 只能调用一次）。

⌨️ 人类命令（slash command）

以 / 开头的指令，由 ctx.commands 注册与分派，不会变成模型消息。它既不同于面向模型的「工具」，也不同于 ctx.shell 执行的 shell 命令。例：/compact、/goal、/plan、/permission。

一张表：四种「扩展」的区别

扩展方式谁触发典型用途
Skill模型按需加载 / 用户显式调用可复用的操作手册与领域知识
MCP 服务器模型调用其暴露的工具接入外部工具生态（数据库、浏览器、SaaS）
Extensions（动态插件）模型写、审批后挂载运行时自我改装、临时能力
Commands人类输入 /xxx不需要模型介入的快捷操作

🧪 小测验
模型在会话里看到的「技能目录」通常包含什么？
答案：B。目录只含 name 与规范化描述（≤500 字）；正文在模型真正调用 skill({name}) 时才按需读取。
🧪 小测验
人类命令（如 /compact）与「工具」最本质的区别是？
答案：B。命令属于「命令平面」，由 ctx.commands 分派，无需模型轮次；工具是面向模型的调用能力。
