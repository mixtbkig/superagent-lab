为什么需要 Harness？

你也许用过 ChatGPT、Claude 或 DeepSeek 的聊天框。它能写诗、能解释代码，但它不会自己去你的电脑上改文件、跑测试、查文档。把「会说话的模型」变成「能干活的智能体」的那层软件，就叫 agent harness。

🎯 学完这一章，你会明白
  • 大模型本身能做什么、不能做什么；
  • harness（智能体框架）到底是什么，它替模型做了哪 6 件事；
  • Claude Code、Codex、DeepSeek Harness 三者的共性与关键差异；
  • 为什么 DeepSeek Harness 值得从头学一遍。
🧸 小学生版：大脑与身体

想象一个特别聪明、但只剩一个大脑泡在玻璃缸里的科学家。他什么都懂，却看不见、拿不动笔、也记不住上一秒想了什么——因为每次问他话，他都会「失忆重启」。

你要让他真的帮你做完作业，就得给他装一套 身体：眼睛（读文件）、手（写文件）、腿（跑命令）、记事本（记下做过的事）、还有一位保姆（防止他乱来）。

大模型 = 玻璃缸里的大脑；harness = 那套身体 + 保姆。Claude Code、Codex、DeepSeek Harness，本质上都是不同厂家造的「身体」。

先看清：大模型到底是个什么东西

从工程角度看，一个大语言模型（LLM）就是一个函数：

一段文本 （prompt）
→
大模型 预测下一个 token
→
下一段文本 （completion）
模型只会「接着往下写」。它没有手、没有硬盘、没有跨请求的记忆。

它有三个天生的限制，正好对应 harness 要补的三件事：

🙈看不见世界
它不知道你磁盘上有什么、测试有没有过、现在是几点。需要 harness 把「世界」塞进它的输入。
✋动不了手
它能说「你应该运行 npm test」，但不会真的去跑。需要 harness 把「说」翻译成「做」。
🧠记不住事
每次请求都是独立的。需要 harness 保存完整历史，再在每次请求时重新喂给它。

Harness 到底做了什么：六件事

把任何一个现代 agent harness（无论闭源还是开源）拆开，你几乎都能找到下面六件事。DeepSeek Harness 只是把它们做得特别「模块化」。

1
组装上下文
把系统提示词、历史消息、当前文件内容、可用工具清单，拼成一次模型请求。system prompt + history + tools
2
调用模型
把请求发给 LLM，流式接收回复（文字、思考、工具调用）。
3
解析工具调用
模型说「我要调用 read 工具读 a.ts」。harness 把这段结构化 JSON 解析出来。
4
执行工具
真正去读文件、写文件、跑 shell、查网页……再把结果整理成模型能读的内容。
5
记录一切
把用户说了什么、模型回了什么、调了哪些工具、结果如何，全部写进会话日志。
6
循环，直到完成
把工具结果加回上下文，再问模型「下一步？」——如此往复，直到模型不再要工具、任务结束。同时全程有安全护栏。
第 1–2 步、第 3–6 步会不断循环，这就是下一章要讲的 Agent 循环。
💡 一句话记住

Harness = 上下文工程 + 模型调用 + 工具执行 + 状态记录 + 循环控制 + 安全护栏。模型是「大脑」，这六件事是「身体和神经系统」。谁把这六件事做得更清晰、更可替换、更可回放，谁的 harness 就更好维护。

三个真实的 Harness，有什么不同？

你提到的 Claude Code（Anthropic）、Codex（OpenAI）和 DeepSeek Harness（DeepSeek）都属于「命令行的编码智能体」这一类。它们面对的问题几乎一样：读代码、改代码、跑命令、查资料、完成多步任务。差别主要在架构哲学。

有意思的是，DeepSeek Harness 甚至内置了把子任务委派给真实 Claude Code / Codex 会话的能力——仓库里有 subagent-claude-code 和 subagent-codex 两个包。也就是说，它可以「站在别的 harness 肩膀上」干活。此外还有一个 claude-code-mods 兼容层，能加载为 Claude Code 写的 hook 模组。这些设计会在第 13、14 章细讲。

为什么值得专门学 DeepSeek Harness？

Claude Code 和 Codex 很好用，但它们是「成品」，你很难看清里面怎么转。DeepSeek Harness 不一样——它从一开始就是奔着可拆解、可替换去设计的：

一切皆插件
连 Agent 主循环、工具注册表、会话日志都是插件，可以从配置里整体换掉。
事件溯源
所有发生过的事都记成一条不可变的日志，模型的「记忆」是从日志里算出来的，可回放、可恢复。
能力 seam
「文件系统」「shell」「模型」「子代理」这类能力被抽象成可替换的接口，本地/远程/沙箱版随意切换。
文档即源码
仓库自带大量中文架构文档与逐子系统参考，学习者友好。
🗺️ 接下来的路线

这一章我们只建立了「harness 是身体」的直觉。下一章，我们把身体里最核心的那台发动机——Agent 循环——单独拆出来转一圈。你会看到「模型要工具 → 执行工具 → 结果回填 → 再问模型」这个循环，正是所有 harness 的心跳。

🧪 小测验
下面哪一项不是 harness 的职责？
答案：C。Harness 是模型外面的「身体」，它从不改模型权重。它负责上下文、调用、工具、记录、循环与安全；训练是另一件完全不同的事。
🧪 小测验
Claude Code、Codex、DeepSeek Harness 最本质的共同点是什么？
答案：B。它们都是 harness，都在补「看不见、动不了、记不住」这三个短板，只是架构哲学与扩展方式不同。DSH 的特别之处是「一切皆插件 + 开源」。
