Agent 的最小循环

所有 agent harness 的心脏，都是一个朴素的循环：问模型 → 模型要工具 → 执行工具 → 把结果告诉模型 → 再问模型。循环到模型不再要工具为止。理解了这个循环，你就理解了 DSH 里 80% 的代码在干什么。

🎯 学完这一章，你会明白
  • 为什么「一问一答」不够，必须要循环；
  • 一次任务如何被拆成「轮次（turn）」和「步骤（step）」；
  • 模型调用、工具调用、工具结果三者在循环里的位置；
  • DSH 里哪个包实现这个循环，为什么它被设计成「可替换」。
🧸 小学生版：让同学帮你做手抄报

你对同学说：「帮我做一张关于恐龙的手抄报。」他不会一秒钟交卷，而是：

  1. 想了想：「我得先查资料」→ 要工具（借一本恐龙书）；
  2. 看完书：「还要彩笔」→ 又要工具；
  3. 画完：「帮我看看哪里要改」→ 你给反馈；
  4. 改完：「做完了！」→ 不再要工具，任务结束。

每一步都是「他先想（Reason）、再动手（Act）、然后看结果（Observe）」。这个 Reason → Act → Observe 的循环，就是 Agent 循环。

为什么不能「一问一答」？

因为模型只能输出文本。当它说「我需要读一下 config.ts」时，这句话本身不会让文件被打开。必须有 harness 在中间做翻译：

用户：修好登录 bug
→
模型：我要调用 read("auth.ts")
→
harness 执行 read返回文件内容
→
模型：我要调用 edit(...)
模型每「要一次工具」，就产生一次新的请求；harness 负责执行并把结果喂回去。

一次任务的工具调用次数是不确定的：可能 1 次，也可能 50 次。所以 harness 必须写成一个循环，而不是一条直线。

两个关键单位：轮次（Turn）与步骤（Step）

DSH 用两个词精确描述循环，这对后面读源码非常关键：

🔁 步骤 Step

一次模型请求 + 它引发的工具执行。

模型说「读文件」，你执行，拿到结果——这算一个步骤。一个步骤里可以并行调多个工具。

🌀 轮次 Turn

一次「把用户输入干完」的全过程，包含零个或多个步骤。

从领取用户消息开始，到不再欠任何工作（模型不再要工具、也没有新消息）结束。日常说「这一轮对话」。

所以关系是：一次轮次 ⊇ 多个步骤 ⊇ 一次模型请求。任务越复杂，一个轮次里的步骤越多。

Turn 开始领取用户消息
→
Step 1
模型→工具 Step 2
模型→工具 Step 3
模型→收尾
→
Turn 结束不再欠工作
一个 Turn 里串起若干 Step；Step 3 模型不再要工具，Turn 收尾。

💡 一个容易被忽略的点

注意上面每一步都先写日志、再行动：turn/start → user/message → step/start → assistant/message → tool/call → tool/result → step/end → turn/end。DSH 有一条铁律叫 「模型可见 ⟺ 已记录」：凡是模型能看到的东西，必须先能在会话日志里被重建。这是第 5 章的主线。

DSH 里谁在转这个循环？

这个循环在 DSH 里叫 agent loop，由 packages/core/agent-loop 这个包实现（具体是一个叫 AgentLoop 的插件）。它对外暴露两个东西：

服务 / 概念作用位置
ctx.agentsAgent 的注册表：创建、恢复、查询、取消一个 agentpackages/core/agent
ctx.agentLoop默认的循环驱动器：真正执行 turn/step 的引擎packages/core/agent-loop
Agent 接口UI、hook、编排器编程时面对的「活动句柄」：send / inject / steer / cancelpackages/core/agent/src/types.ts

它被设计成插件而不写死在核心里，所以理论上你能写一个完全不同的循环替换它——这正是「一切皆插件」的威力（第 2 章会讲）。

packages/core/agent-loop — 循环的核心轮廓（示意，非逐字源码）
async function driveTurn(agent) {
  const input = claimNextStepInput(agent.inbox)   // 领取用户消息
  await session.append({ type: 'turn/start', turn })
  try {
    for (;;) {
      await session.append({ type: 'step/start', turn, step })
      const messages = deriveMessages(session)       // 从日志派生历史
      const request  = assembleRequest(systemPrompt, messages, tools)
      const answer   = await llm.stream(request)     // 流式请求模型
      await session.append({ type: 'assistant/message', ...answer })
      if (answer.toolCalls.length === 0) break       // 不再要工具 → 收尾
      for (const call of answer.toolCalls) {
        await session.append({ type: 'tool/call', ...call })
        const result = await tools.execute(call)     // 走受保护的执行流水线
        await session.append({ type: 'tool/result', ...result })
      }
      await session.append({ type: 'step/end', turn, step })
      step++
    }
  } finally {
    await session.append({ type: 'turn/end', turn, reason })
  }
}

上面的代码是为了帮你建立直觉而写的「骨架」。真实的 agent-loop 要处理取消、重试、流式 chunk、pre-step 钩子、运行时上下文注入、工具并发、失败恢复……这些我们会在第 6 章逐个补上。

⚠️ 常见的误解

「模型决定什么时候结束」——对，但也不完全对。模型「不再调用工具」只是自然停止的一种情况；harness 还可能因为：没有新输入、被取消、达到最大轮数、触发终止策略（如 goal 完成、计划退出）而结束这一轮。控制权在 harness，不在模型。

🧪 小测验
「一次模型请求 + 它引发的工具执行」在 DSH 里叫什么？
答案：B（步骤 Step）。轮次（Turn）更大，包含零个或多个步骤；会话（Session）是整段对话的日志；目标（Goal）是跨轮次的持久任务。
🧪 小测验
模型回复「我已经改好了」且没有要求任何工具，此时 Loop 会怎样？
答案：B。没有工具调用 = 自然停止。Loop 会关闭当前步骤与轮次，Agent 回到 idle。
